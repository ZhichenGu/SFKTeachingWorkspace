# SFK 教学工作台

只处理学生上课签单：填写、发链接、学生签名、管理页自动更新、下载与删除。课程类型默认“项目课”，也可选“基础/软件课”。当前按用户要求采用公开共享工作台：无需登录，所有访问者可查看、创建、修改、删除全部签单。

## 第一次配置 Supabase

`config.js` 已填写本项目的 Project URL 与 Publishable key。Project ID 为 `gsbktszybeqhpyirvcaw`，URL 为 `https://gsbktszybeqhpyirvcaw.supabase.co`。公开密钥适合放在前端；不要换成 service_role / secret key。

1. 打开 [Supabase 项目](https://supabase.com/dashboard/project/gsbktszybeqhpyirvcaw)。进入 **SQL Editor → New query**，复制同目录 `supabase.sql` 的完整内容，执行一次。脚本创建表、权限与签名接口；重复执行不会删除记录。
2. **不需要创建老师账号或配置 Authentication。** 如果此前执行过带登录要求的旧脚本，重新执行当前 `supabase.sql`，它会将读取与管理接口改为公开共享权限，保留已有记录。
3. 上传或提交本目录所有网站文件到 GitHub，而不仅是 `index.html`。GitHub 仓库 **Settings → Pages** 选择 `main` 分支根目录。若部署地址不同，修改 `config.js` 的 `siteUrl`。当前预设为 `https://zhichengu.github.io/SFKTeachingWorkspace/`。
4. 直接打开网站，新建一份测试签单，生成链接；在另一浏览器或手机打开链接签名。管理页面可见时约 15 秒内更新，也可点击“刷新签名状态”。

**不需要创建 Storage bucket，不需要 Edge Function，不需要在前端放数据库密码。** 建表脚本未执行前，不能将学生签名自动同步视为已启用。

## 使用

- 首页：按学生姓名搜索；按日期范围筛选；按上课时间或姓名排列；查看“待签名 / 已签名”。
- 新建：依次填写课程类型、学生姓名、上课内容、课后作业、导师签名；其他课次与日期时间字段在后面。默认日期取设备当地日期，时间每半小时一档。
- 点击“生成学生签名链接”会先保存记录。非关键空项不拦截生成，学生签名不作为发出链接前的必填项。学生姓名用于管理检索，需要填写。
- 学生专用链接直接展示对应记录和签名按钮。链接有效期 30 天；每份记录只接受一次学生签名提交。重复请求不会覆盖已有签名。专用页面是便捷入口，不是独立权限隔离：打开主站的任何人仍可管理全部记录。
- 老师修改已签名的课程内容或导师签名并保存后，旧学生签名清空、旧链接失效；重新生成链接请学生确认。教师签名未变的重复保存不会使链接失效。
- 删除按钮只确认一次；删除后记录、签名和链接均失效，不可恢复。可先下载留档。
- 勾选多份记录，或全选当前筛选结果，点击“批量下载图片 ZIP”。每份 PNG 以学生姓名、日期和短编号命名。个别文字溢出或请求失败的记录会列出原因，其余文件继续下载。批量下载使用保存后的记录，未保存的编辑不包含在内。
- PNG 和浏览器打印 PDF 使用同一个 A4 版式。超出 A4 可容纳范围的文字会提示缩短，不能静默截断。留空字段可以继续导出。

## 批量填写（一次一批）

管理页点「批量新建」：顶部设本批次的默认课程类型、日期、时间和导师签名；下面一行一名学生，可编辑学生、课程类型、日期、时间、上课内容、课后作业，第几次课与作业完成情况收在行内「更多」里。桌面是表格，手机变成逐份卡片，可「上一份 / 下一份」切换，底部固定「批量保存并生成链接」。

- 新增行继承默认值，单行可改课程/日期/时间；留空即继承。
- 上课内容、课后作业在单元格里以单行摘要显示，聚焦时展开编辑，避免长文本撑坏列表。
- 行内操作：「沿用上次」按姓名取该学生最近一份签单、第几次课自动 +1；「复制上一行」复用上一行字段；「更多」展开课次与作业完成；「删除」移除该行。
- 学生姓名框带历史联想（来自已保存记录）。
- 「批量保存并生成链接」：逐份保存并生成签名链接，每份带「复制链接」按钮与「已复制」标记，可一键复制全部链接文本。学生姓名必填，其余空项不拦截。单行失败单独列出，不影响其他行；保存失败的行不会出现链接。
- 草稿自动保存在本机，刷新/切设备前不丢；生成成功后才清空草稿。
- 导师签名与课程类型作为「常用默认值」持久化：新建单签与批量都会自动带入，保存后回写。

## 自动保存与常用默认值

- 单签编辑器：新建（尚未签名、未发链接）时输入停顿 2 秒自动保存；状态栏明确显示「未保存 / 保存中… / 已保存 / 保存失败」，只有服务器确认成功才显示「已保存」。已签名或已发链接的记录仍手动保存，避免误改自动清空学生签名或使链接失效。
- 导师签名、课程类型存为常用默认值，下次新建自动带入。
- 电脑与手机同时打开同一记录时沿用现有 revision 检查，冲突提示、不静默覆盖。

## 字体与导出版式

- 填写界面继续用系统字体，加载快、输入自然。
- 预览、文字测量与导出使用**随站点发布的自托管字体** `SFK Serif SC`（Noto Serif CJK SC 的子集，SIL OFL 许可，许可见 `fonts/OFL.txt`），不依赖设备是否安装 Kaiti/Songti。字体加载完成后才重绘预览，导出前等待 `document.fonts.ready`。
- 姓名文字签名在保存时转成小图片固化，跨设备查看不再重新排字，与画笔/上传签名一致。
- 字体未覆盖到的生僻字回退到系统字体，由自动换行兜底，不静默截断。

## 空间与清晰度

云端保存课程文字与两份轻量签名，**不保存整张 A4 图片**。输入姓名只保存少量文字；画笔签名转为小图；上传的签名图片缩放、压缩为每张最多 16 KB。优先保留 PNG，无损压缩不足时使用白底 JPEG。上传签名建议先裁去多余背景。

数据库中的 Base64 编码比原图片字节数约增加三分之一，另有 JSON、行、索引开销。因此“16 KB”是单张签名的图片字节上限，并非整条数据库记录大小。两张图片上限约 32 KB，Base64 约 43 KB，再加文字与数据库开销；文本签名通常远小于这个值。

下载时浏览器生成 1588 × 2246 的 A4 PNG，清晰度优先，文件通常超过十几 KB，但不占用 Supabase 图片存储。将整张 A4 强制压到十几 KB 会明显影响中文与签名辨认，因此没有这样处理。

[Supabase 官方数据库容量说明](https://supabase.com/docs/guides/platform/database-size)：免费计划当前数据库配额为 500 MB，已有系统表等也会占用空间；不能把全部额度当成签单可用容量。轮询只获取轻量列表元数据，不每次读取签名图片；详情或下载时才读取整条记录。

## 文件与数据边界

| 文件 | 职责 |
| --- | --- |
| `index.html` | 基础表单、数据 schema、三种签名编辑器、A4 SVG 渲染、单份打印和导出 |
| `sharing.js` | 高频字段排序、记录装载、学生只读查看与提交流程 |
| `workspace.js` | 公开管理页、列表检索排序、多选、保存、自动刷新、删除、常用默认值与自动保存 |
| `batch.js` | 批量填写（表格/卡片分页）、行操作、姓名联想、批量生成链接与复制 |
| `fonts.js` | 自托管正文字体 `@font-face`、字体加载完成后重绘 |
| `fonts/` | `NotoSerifSC-subset.woff2` 与 `OFL.txt` 许可 |
| `cloud.js` | Supabase HTTP 调用、签名压缩与固化、读入数据校验 |
| `exports.js` | 按记录生成 PNG、无第三方依赖的 UTF-8 ZIP 打包 |
| `config.js` | 网站地址与公开 Supabase 配置 |
| `supabase.sql` | 数据表、公开读取 RLS、写入校验 RPC、版本冲突检查、链接有效期 |

数据主对象包括 `schemaVersion`、`studentName`、`courseName`、`lessonDate`、`lessonNumber`、`checkIn`、`checkOut`、`content`、`homework`、`previousHomework`、`signatures.student/mentor`。表单中保留签名三种方式的草稿；入库只保留当前选中方式。数据库使用 `revision` 避免旧页面覆盖学生刚提交的签名；遇到冲突先显示错误，不强制覆盖。

`polishService.provider` 是未来 AI 润色接入点：输入字段、原文、课程上下文和取消信号，返回建议文字。当前没有任何 AI API 调用、模型名依赖或密钥。未来应由服务端保管模型密钥，建议文字由老师采用后再写回字段。

## 已修正的流程规则

- 不为调整字段、切换签名方式、清除重签等可逆操作反复确认。
- 不因课次等非关键空项阻止预览或发链接；导出统一提示空项。
- 不把“链接生成”“图片下载”误算成“学生已签名”；状态来自实际签名提交。
- 不把公开静态网页当作能保存签名的服务器；共享持久化只由 Supabase 承担。当前不添加账号、登录或身份校验流程。
- 不轮询整张图片；不在云端保存重复的整页 A4 预览。
- 导出、预览共用渲染器，避免两套模板漂移；批量下载逐份生成，失败单独列出。
- 不因切换手机尺寸清除笔迹；异步上传有版本号，清除后旧上传不能重新出现。
- 删除一次确认；修改已签记录后使旧链接失效；重复提交幂等，不重复创建记录。
- 仅未保存编辑触发离开提示；已保存记录和刚打开的默认表单不反复阻拦。
- 项目目前无需构建、第三方字体、CDN、独立服务器、全套设计系统。
